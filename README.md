# Последний круг — сервер и база данных

API игры и база данных. Сама игра — в ветке [`main`](../../tree/main). Рабочая версия: http://176.124.223.180/

```
backend/              API: регистрация, вход, сессии, прогресс
migrations/, scripts/ PostgreSQL: схема, миграции, бэкапы
tests/                тесты базы
docs/                 схема, ER-диаграмма, подробности о базе
docker-compose.yml    база + API
```

## Стек

- **Python 3.12, FastAPI, Uvicorn** — API.
- **psycopg 3** с пулом соединений, чистый SQL без ORM.
- **PostgreSQL 17** — база.
- **Docker Compose** — база, API и служебный контейнер с psql в одном файле; на компьютере не нужны ни Python, ни PostgreSQL.
- На сервере: Ubuntu, nginx отдаёт игру и проксирует `/api` на бэкенд.

## Что умеет

| Метод  | Путь             | Что делает |
| ------ | ---------------- | ---------- |
| `POST` | `/auth/register` | регистрация по никнейму и паролю |
| `POST` | `/auth/login`    | вход, выдаёт токен |
| `GET`  | `/auth/me`       | текущий игрок |
| `POST` | `/auth/logout`   | отзыв сессии |
| `GET`  | `/progress`      | прогресс игрока |
| `PUT`  | `/progress`      | сохранить прогресс (можно частично) |
| `GET`  | `/health`        | проверка, что база доступна |

## Особенности

- **Безопасность.** Пароли хранятся как PBKDF2-хеш с солью, токены сессий — как SHA-256 хеш. Сессия живёт 30 дней, выход её отзывает.
- **Разделение ролей в базе.** Суперпользователь только создаёт роли, `last_lap_migrator` владеет схемой и запускает миграции, `last_lap_user` — роль API: читает и пишет данные игры, но не может менять схему.
- **Прогресс** хранится в JSONB и сохраняется функцией базы `save_game_progress`; ограничения проверяют формат данных, триггеры обновляют `updated_at`.
- **Миграции** — нумерованные SQL-файлы и скрипт `migrate.sh`.
- **Бэкап и восстановление** — скрипты `backup.sh` и `restore.sh`.
- **101 тест базы**: схема, ограничения, транзакции, триггеры, права ролей, бэкап и восстановление.
- Ошибки приходят как `{ "message": "текст для игрока" }` — фронтенд показывает их как есть.

## Запуск

Нужен Docker.

```bash
cp .env.example .env          # заменить пароли, например: openssl rand -hex 24
docker compose up -d --wait postgres
docker compose run --rm tools bash scripts/migrate.sh up
docker compose up -d --build --wait backend     # API на http://localhost:8000
```

Тесты: `docker compose run --rm tools bash scripts/test.sh`. Подробно о базе — `docs/DATABASE.md` и `docs/SCHEMA.md`.

Чтобы подключить игру, во фронтенде создайте `.env.local` с `VITE_API_URL=http://localhost:8000`.
